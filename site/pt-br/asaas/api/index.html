Referência da API

Toda operação da especificação oficial da API v3 do Asaas existe aqui, com autenticação, validação e o formato de erro do Asaas. Comportamento real quer dizer um motor de negócio com estado; as demais respondem 501 nomeando a operação, nunca dado falso.

Convenções

  • URL base: http://localhost:45445/v3.
  • Autenticação: o header access_token com a chave da conta, como no Asaas. Cada chave é uma conta, com walletId e saldo próprios.
  • Erros: HTTP 400 com {"errors":[{"code":"…","description":"…"}]}, os códigos e frases que o Asaas manda (um cartão recusado é invalid_action, não invalid_creditCard).
  • Listas: offset e limit, com totalCount e hasMore na resposta.
  • Dinheiro: guardado em centavos inteiros por dentro, respondido em reais como no Asaas.

As operações /v3

Abra uma operação para ver os parâmetros, os campos do corpo, um exemplo de requisição e cada resposta com o seu exemplo, erros incluídos, tirados da especificação oficial.

Rotas de controle de pagamento

Atalhos sem chave em /_mock levam um pagamento a um estado numa chamada, para testes: listar, confirmar, receber, vencer, falhar (apelido de vencer) e estornar (total ou parcial). As transições são as mesmas da API: status, extrato, webhooks.

curl localhost:45445/_mock/payments?limit=10
curl -X POST localhost:45445/_mock/payments/pay_123456789012/confirm
curl -X POST localhost:45445/_mock/payments/pay_123456789012/receive
curl -X POST localhost:45445/_mock/payments/pay_123456789012/overdue
curl -X POST localhost:45445/_mock/payments/pay_123456789012/refund \
  -H 'content-type: application/json' -d '{"value": 50.00}'

Prefira POST /v3/sandbox/payment/{id}/confirm e …/overdue, do próprio sandbox, quando o seu código também puder rodar contra o sandbox real.
