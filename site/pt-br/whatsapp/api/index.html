Referência da API

Toda operação da especificação v23.0 da Meta é roteada e validada. Comportamento real quer dizer que o mock a simula com estado; as outras respondem com o próprio exemplo da Meta, válido contra o schema de resposta.

Convenções

  • URL base: http://localhost:3010/v23.0, o mesmo caminho da Meta.
  • Autenticação: Authorization: Bearer <qualquer token>. Uma chamada sem token é recusada, como na Meta.
  • Erros: o envelope da Meta, {"error":{"message","type":"OAuthException","code","error_data","fbtrace_id"}}, com os códigos da Meta.
  • Webhooks: o corpo entry[].changes[] da Meta, assinado com x-hub-signature-256 quando WEBHOOK_SECRET está definido.
  • Versões: cada versão da Graph é a sua própria especificação; uma nova é uma nova pasta spec/<versão>.

A aba API do painel traz as mesmas operações, com um curl pronto para cada uma.

Headers de teste

O que só um teste precisa vai em headers opcionais, nunca no corpo, para o corpo continuar sendo o que a Cloud API espera.

HeaderEmO que faz
X-Mock-FromPOST /{phone}/messages, /callsA chamada sai do celular do usuário: uma mensagem, uma confirmação, uma ligação
X-Mock-Contact-NameidemO nome de perfil que o seu webhook vê
X-Mock-Message-Statusuma confirmação com X-Mock-Fromdelivered, read ou failed
X-Mock-Template-Reviewcriar e editar templateAPPROVED (padrão), REJECTED, PAUSED, DISABLED, PENDING
X-Mock-Template-Review-ReasonidemO motivo no webhook de status
X-Mock-Template-Review-DelayidemQuanto a revisão demora, em ms (até 10 minutos)

As rotas /settings

Só para o que a Meta não tem endpoint: os ajustes do próprio mock, como o atraso de resposta do webhook, o modo de entrega e o histórico de ligações (GET /settings/calls). A lista com os corpos está em docs/panel.md.
