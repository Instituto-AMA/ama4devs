Run it on your machine.

Four ways, from the fastest to the most complete. The images are public: no login.

Ready image

The fastest way: the image straight from GHCR.

WhatsApp mock

docker pull ghcr.io/instituto-ama/whatsapp-mock:latest
docker run -d -p 3010:3010 ghcr.io/instituto-ama/whatsapp-mock:latest

Panel and API at localhost:3010

Asaas mock

docker pull ghcr.io/instituto-ama/asaas-mock:latest
docker run -d -p 45445:45445 -e CLOCK_MODE=VIRTUAL_FLOWING \
  ghcr.io/instituto-ama/asaas-mock:latest

Panel and API at localhost:45445, with the virtual clock on. Asaas finds WhatsApp, Mailpit, the SMS mock and the generator by itself: every charge already tells the payer by e-mail, WhatsApp and SMS, each one when the customer has that contact.

SMS mock

docker pull ghcr.io/instituto-ama/sms-mock:latest
docker run -d -p 8899:8899 ghcr.io/instituto-ama/sms-mock:latest

Panel and API at localhost:8899: the payer's phone inbox.

Generator

docker pull ghcr.io/instituto-ama/generator-mock:latest
docker run -d -p 45450:45450 ghcr.io/instituto-ama/generator-mock:latest

UI and API at localhost:45450

Mailpit, the payer e-mail inbox

docker run -d -p 8025:8025 axllent/mailpit:v1.31.4

Inbox at localhost:8025

In your docker-compose

To run next to your application, in its compose. Nothing to wire: Asaas finds WhatsApp, Mailpit, the SMS mock and the generator by service name.

services:
  asaas:
    image: ghcr.io/instituto-ama/asaas-mock:0.13.0
    ports:
      - '45445:45445'
    environment:
      ASAAS_API_KEY: '$$aact_hmlg_local'   # `$$` is a literal `$` in compose
      CLOCK_MODE: VIRTUAL_FLOWING
    depends_on: [whatsapp, mailpit, sms, generator]
    volumes:
      - asaas-data:/data

  whatsapp:
    image: ghcr.io/instituto-ama/whatsapp-mock:0.5.0
    ports:
      - '3010:3010'
    environment:
      WEBHOOK_URL: http://my-app:4000/webhooks/whatsapp   # your application
      MOCK_ALLOWED_HOSTS: whatsapp   # your application calls it by this name
    volumes:
      - whatsapp-data:/app/data

  mailpit:
    image: axllent/mailpit:v1.31.4
    ports:
      - '8025:8025'

  sms:
    image: ghcr.io/instituto-ama/sms-mock:0.2.0
    ports:
      - '8899:8899'

  generator:
    image: ghcr.io/instituto-ama/generator-mock:0.5.0
    ports:
      - '45450:45450'
    environment:
      ASAAS_API_KEY: '$$aact_hmlg_local'   # the same key, to fill the Asaas mock

volumes:
  asaas-data:
  whatsapp-data:

From your application: http://asaas:45445/v3 and http://whatsapp:3010/v23.0. The fake data at http://generator:45450/v1. The payer e-mails at localhost:8025, the payer WhatsApp at localhost:3010 and the payer SMS at localhost:8899.

Build from source

To run from the source, or after changing a mock.

git clone https://github.com/Instituto-AMA/ama4devs.git
cd ama4devs

WhatsApp mock

docker build -t whatsapp-mock mocks/whatsapp
docker run -d -p 3010:3010 whatsapp-mock

Asaas mock

docker build -t asaas-mock mocks/asaas
docker run -d -p 45445:45445 -e CLOCK_MODE=VIRTUAL_FLOWING asaas-mock

SMS mock

docker build -t sms-mock mocks/sms
docker run -d -p 8899:8899 sms-mock

Generator

docker build -t generator-mock mocks/generator
docker run -d -p 45450:45450 generator-mock

With WhatsApp, Mailpit and the SMS mock up, Asaas finds them by itself, as with the ready image, and the generator finds Asaas.

Run everything

All four mocks and Mailpit, wired together. Every Asaas charge tells the payer three ways: an e-mail in Mailpit, a WhatsApp template through the WhatsApp mock and an SMS in the SMS mock, each one when the customer has that contact. The generator fills the account with test data on demand.

git clone https://github.com/Instituto-AMA/ama4devs.git
cd ama4devs
make setup        # starts everything and writes the addresses into .env

A pool of mocks.

Each mock is one Docker image for linux/amd64 and linux/arm64. It boots fully configured, keeps its state in a volume and comes with a panel that shows what the real API never lets you see. Three provider APIs and a data generator are ready today; more payment providers and banks are on the way.

WhatsApp mock

The Cloud API of the Meta Graph API v23.0, routed and validated against Meta's own OpenAPI file, plus a WhatsApp Web like panel where you are the user on the other side.

  • Messages of every type, templates with a review, media, voice notes, receipts.
  • Voice calls with real WebRTC audio and the user's call permission.
  • Business, WABAs and numbers with the SMS code onboarding.
  • Webhooks signed with x-hub-signature-256.
Quick start Use cases API Docs

Asaas mock

The Asaas API v3, the Brazilian payment gateway, with the business rules captured from the real sandbox and a virtual clock you move by hand.

  • Customers, Pix, boleto, credit card, installments, subscriptions, splits.
  • Webhooks delivered to localhost, with the real retry rules.
  • A clock you advance: charges go overdue, cards credit at D+32.
  • Saved cards charged on the due date, with Asaas's retries.
  • Payer notifications by e-mail, WhatsApp and SMS.
Quick start Use cases API Docs

SMS mock

An SMS gateway that answers like a real one: a native API, the Twilio-compatible one and a simple GET/POST, with the message lifecycle running and the webhooks going out.

  • Three API shapes: native, Twilio-compatible and a simple one, with a long poll for the tests.
  • The lifecycle runs: queued, sent, delivered — and magic numbers that fail on purpose.
  • GSM-7 and UCS-2 segments counted, and the OTP code pulled out for you.
  • Status and inbound webhooks signed with x-sms-signature.

Generator

Valid fake Brazilian data, the same for the same seed: people, companies, CPF, CNPJ, CNH, PIS, RG, addresses with real CEP ranges, cards, bank accounts and Pix keys. It fills the Asaas mock and answers the Direct Data credit check at the provider's own paths.

  • Every Brazilian document, valid and masked: CPF, CNPJ, CNH, PIS, RG, CEP, cards, accounts, Pix keys.
  • One call populates the Asaas mock with customers and charges.
  • The Direct Data credit check, at the provider's own paths.
  • The same UI runs in the browser, with no container.
