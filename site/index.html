WhatsApp and Asaas, running on your machine.

Two mock servers for local development, automated tests and CI. Point your application at localhost instead of the real API: same paths, same bodies, same webhooks. No account, no credential, no bill.

Two mocks, one per API

Each one is a single Docker image for linux/amd64 and linux/arm64, boots fully configured and keeps its state in a volume.

WhatsApp mock

The WhatsApp Cloud API of the Meta Graph API v23.0, simulated from Meta's own OpenAPI specification, plus a WhatsApp Web like panel where you are the user on the other side.

  • Messages of every type, templates with a review, media, reactions, receipts.
  • Voice calls with real WebRTC audio, call permissions, voice notes.
  • Business, WABAs and phone numbers with the SMS code onboarding.
  • Webhooks signed with x-hub-signature-256.
docker run --rm -p 3010:3010 ghcr.io/instituto-ama/whatsapp-mock:latest
Read the WhatsApp mock docs

Asaas mock

The Asaas API v3, the Brazilian payment gateway, with the business rules captured from the real sandbox and a virtual clock you move by hand.

  • Customers, charges with Pix, boleto and credit card, installments, subscriptions.
  • Webhooks delivered to localhost, with the real retry rules.
  • A payer invoice page with a real Pix QR code.
  • Payer notifications by e-mail and WhatsApp.
docker run --rm -p 45445:45445 ghcr.io/instituto-ama/asaas-mock:latest
Read the Asaas mock docs

Both together

The repository's compose file runs the two mocks and Mailpit. Every charge the Asaas mock creates tells the payer twice: an e-mail that lands in Mailpit and a WhatsApp template sent through the WhatsApp mock's Cloud API. Everything comes up configured, with no step by hand.

git clone https://github.com/Instituto-AMA/ama4devs.git
cd ama4devs
make setup        # starts the mocks and writes their addresses into .env
ServiceAddressWhat you open there
WhatsApp mockhttp://localhost:3010The chat panel, templates, numbers, calls; the API at /v23.0
Asaas mockhttp://localhost:45445The simulator's panel; the API at /v3
Mailpithttp://localhost:8025The e-mails sent to payers

To point another application at them: make setup TARGET_ENV=../my-app/.env.
